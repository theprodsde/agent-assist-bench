# Requests for Comments (RFCs)

AgentAssistBench uses RFCs to discuss design proposals before they become Architecture Decision Records (ADRs).

## RFC vs. ADR

| | RFC | ADR |
|---|-----|-----|
| **Purpose** | Propose and discuss | Document a decision |
| **Status** | Open, Under Discussion, Resolved | Proposed, Accepted, Deprecated |
| **Outcome** | May become an ADR, or be rejected | Guides implementation |
| **Audience** | Anyone with opinions | Implementers and future readers |

## Engineering Workflow

```
Idea → RFC → Discussion → Decision → ADR → Implementation
```

## Open Questions (Future RFCs)

The following questions are intentionally left undecided and will be resolved through the RFC process as the project progresses:

1. Which cloud provider should be implemented first (Azure, GCP, or AWS)?
2. What delay should be used between sequential executions?
3. How should browser automation metrics be standardized across agents?
4. What scoring rubric should be used for human evaluation?
5. Should the benchmark support scheduled runs in addition to user-triggered runs?
6. What report formats should be generated by default (Markdown, HTML, PDF)?
7. Which deployment should become the long-term reference environment?
8. Should we support parallel execution as an optional mode?
9. Should PostgreSQL replace SQLite for multi-user scenarios?

## Creating a New RFC

1. Create a file: `RFC-XXXX-short-title.md`
2. Use the template below
3. Open a PR or discussion thread
4. Gather feedback and iterate
5. When resolved: either create an ADR or close as rejected

### Template

```markdown
# RFC-XXXX: Title

**Status:** Open | Under Discussion | Resolved | Rejected  
**Author:** Name  
**Date:** YYYY-MM-DD  
**Related ADRs:** (if applicable)

## Summary

One-paragraph description of what is being proposed.

## Motivation

Why is this change needed? What problem does it solve?

## Proposal

Detailed description of the proposed change.

## Alternatives

Other approaches that were considered.

## Trade-offs

What are the costs and benefits of this proposal?

## Open Questions

Things that still need to be resolved.

## Resolution

*(Filled in when the RFC is resolved)*

- **Decision:** Accepted / Rejected
- **ADR:** Link to resulting ADR (if accepted)
- **Rationale:** Why this decision was made
```
